# 实验准入适配评审与独立 Mac 只读核验

2026-10-30。范围：G1 采集准备、G3 设计评审。没有模型调用、Canary、部署或生产行为变更。配套：[G1/G3 决策](g1-g3-minimal-execution-decision.md)。

## 评审结论

**方案可继续细化，暂不能进入模型实验，也不将其视为已实现的预算控制。**

实验宿主中的传输装饰器可以保持 MCP 与 Agent Loop 独立，但必须覆盖每次新建 Provider、重试和流式 fallback。仅在最外层统计逻辑调用不够。请求数、截止时间可以本地准入；输入、输出、费用须先有可信保守上界。缺少上界就拒绝，不能用事后 usage 或静默改变生成参数代替。

费用应分别记录余额实际扣款、套餐额度消耗和标价估算；`cost=0` 不等于没有消耗。候选 $0.50 究竟约束哪项须在授权前确定。尚未确认的字段不能记为零，也不能用当前 Registry 参考价格保证账单上限。

## 最小接口与不变量

实验 ID、允许的 origin/path/model、截止时间、候选资源限额及上界来源作为宿主只读配置，不接受 MCP 或模型工具修改。每次 Build 完成后检查实际 Provider 链，注入同一计量器；无法识别的 Provider 或 HTTP 客户端拒绝启动。

账本只记录必要的请求指纹、预留、计量及状态，不存 Authorization、提示词或工具源码。由可信控制面持有，工具执行域不得读写。文件必须限制权限、拒绝符号链接，并在资源预留成功持久化后才允许发送。

每次尝试状态为 `reserved → sending → settled / unknown`。本地拒绝另记原因，不占上游请求次数；已经预留但是否发送不确定时保守保留名额和资源。进程重启后不自动重发，不把未决项改为成功或零消耗。

串行单在途请求；准入和持久化预留是一个互斥操作。预算不足、计量器装配失败、账本故障或截止时，拒绝发送并取消实验 context。取消之后仍须等待工具和 Turn 停止，不能直接宣称 Task 完成。

保持原始 body 字节、模型配置和 TLS 校验。关闭代理、重定向与连接复用等隐式发送路径；使用独立连接核对一次 POST 与一次账本发送事件。计数边界是客户端实际发送尝试，不包括 Provider 内部不可见的上游重试。连接失败也保守消耗名额。

流式旁读不能无限缓存或阻塞正常响应。成功、HTTP 错误、SSE 错误和取消均保留已观察到的计量；截断或格式错误记 unknown。重复累计 usage 快照取最新可信累计值，不逐条相加；缺失、显式零和无效数值分开。金额使用精确十进制解析，拒绝负值、溢出及无法解释的计费类别。

## 负向用例评审

以下是**适配实现后的测试要求，目前未实现、未通过**。所有服务器和计费响应使用本地 fake transport/server，不调用 Provider。

| 用例 | 故障输入 | 必须断言的外部证据 |
| --- | --- | --- |
| N1 | 两个调用竞争最后名额；第 13 次；失败重试和 stream fallback | 上游观测不超名额；每次物理尝试有唯一预留；本地拒绝发送数为零 |
| N2 | 下一 Turn 重建 Provider；未知客户端；Host/path/model 不符 | 未装饰链不能运行；未知路由没有拨号；无模型降级 |
| N3 | 301/307/308、代理环境变量、连接中断、隐式重放条件 | 不跟随新地址；不使用环境代理；线上请求与账本逐项对应 |
| N4 | 无 tokenizer/保守输入界、无最大输出界、未知价格、预算不足 | 首次网络发送前拒绝；原 body 与生成参数不变 |
| N5 | HTTP 400/429/500 含 usage；SSE 重复累计 usage 后断流/取消 | 已观察计量保留且不重复相加；未知余量不释放为零 |
| N6 | cost 缺失、零、负数、超大值；套餐与余额分类不同 | 缺失不等于零；非法计量不能释放预留；不同费用类别不混算 |
| N7 | reserve 写入/fsync 失败；预留后、发送后、结算前退出 | 未持久化不发送；未决预留保留；重启不自动重试 |
| N8 | 响应超过预留、字段冲突、超大或损坏 SSE 帧 | 标为预算失守/计量异常并停止；不得把超额隐藏成成功；受限内存旁读 |
| N9 | 假时钟到期、用户取消、预算拒绝触发 resilience | 不再发新请求；在途取消与残留进程有独立停止证据 |
| N10 | 工具尝试改账本或配置；账本为 symlink；请求日志含敏感字段 | 拒绝；假凭据与假提示词不进入日志；真实凭据不用于探针 |
| P1 | 合法两轮请求、工具 JSON、正常 usage 及全部装配路径 | 原始 body hash 一致；工具 JSON 完整；账本可核对；Task 状态仍由原流程决定 |

N8 属于检测和停止，不能倒推此前硬上界已成立。若上界来源不可靠，N4 就应阻止第一次请求；通过异常响应测试不是预算硬保证。

## 独立 Mac 本地核验操作

用户选择在独立 Mac 本地运行，不使用 SSH、不扫描网络。将 [采集脚本](../scripts/inspect-managed-host.sh) 作为普通文本复制到独立 Mac；不复制生产数据库、MCP grant、API Key 或整个 HOME。

在该机 Terminal 运行（替换为实际脚本位置）：

```sh
/bin/sh /实际路径/inspect-managed-host.sh --label independent-mac
```

如果已有计划使用的工作区和 App，可附加 `--workspace /实际工作区`、`--app /实际/Talkify.app`；不要为了采集创建目录、安装软件或启动 Daemon。不要使用 sudo。脚本不读取凭据或项目源码，不联网，不执行 Git/Python 工具链；报告明确路径的元数据、ACL、部分签名声明，并可读取指定 App 的 Daemon 二进制计算 hash。输出含用户名/路径，可在分享前替换个人路径片段并保持对应关系，不提供 Token。

采集只能建立系统和权限清单。服务禁用覆盖项缺失、签名 entitlement 缺失、没有 agent 环境变量均不证明隔离。没有扫描共享配置、所有进程或 Keychain；设备独立性、旧域入站拒绝、模型越界拒绝仍须另行核验。不会因采集脚本返回成功放行 G1。
