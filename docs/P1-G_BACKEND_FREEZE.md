## Independent acceptance

Pre-fix run: 32/33 passed. The only failure was a request-level
`matrix_layout_unavailable` result whose model-visible content contained the
absolute `os.Lstat` path.

Post-fix run (`d39bb99`): **33/33 passed, 0 failed**.

Confirmed invariants:

- Full matrix: 4 targets × 2 states → 8/8 completed cells, coverage complete.
- Subset matrix: only the selected target/state cells are aggregated; lineage
  must declare the same target set.
- Both reference forms resolve: `artifact_key` (latest or pinned revision) and
  explicit `artifact_id` + `revision` (+ optional digest).
- One artifact with multiple revisions is distinguished by revision and digest;
  a pinned r1 and the latest r2 produce different matrix documents.
- Declared failed, unresolvable, missing, and corrupt cells are preserved
  exactly once; they are never silently omitted, and coverage equals the entry
  census.
- Cross-session references, nonexistent revisions, corrupt stored revisions,
  wrong revision digests, and lineage target/state/layout/source/evidence
  mismatches become failed cells with typed errors.
- Request-level errors (target-matrix mismatch, wrong layout/source/evidence
  digest, undeclared target/state, duplicate cells, shared artifacts, malformed
  or path-shaped references, unknown fields) produce no matrix directory.
- Matrix and manifest digests recompute from persisted bytes; manifest is
  regenerated byte-identically; entries follow canonical cell order.
- Replay is idempotent: an identical request reuses the stored revision
  (`created=false`), including from a fresh store instance over the same
  on-disk store.
- Model-visible results and persisted documents contain workspace-relative
  paths only.

## Model-visible errors

A layout-unavailable failure returns only the stable text:

```text
layout revision metadata is unavailable
```

`matrix.Error` separates the model-safe `Message` from a runtime-only
`Diagnostic()`. Raw filesystem causes (`os.Lstat`, permission errors, symlink
resolution failures) and absolute paths remain internal diagnostics and never
enter `ToolResult.Content`, `Failure`, or `Output`. Store-unavailable failures
are projected to `preview store is unavailable`.

Regression tests cover nonexistent revisions, non-regular metadata, permission
errors, and revision-directory symlink escapes at both the matrix backend and
the tool boundary.

## Frozen contracts

- `schemas/ui_preview_matrix.v1.schema.json` and
  `schemas/ui_preview_matrix_result.v1.schema.json` are unchanged by the
  sanitization commit.
- P1-F `ui_preview_result.v1`, `ui_preview_lineage.v1`/`.v2`, preview artifact
  metadata, and revision digests are unchanged.
- Failed and missing cells remain part of the document contract; coverage is
  derived from the actual entry census.
- Completed cells require an adaptation preview, the complete lineage record,
  and fallback asset identity bound to the matrix layout revision.

Any change to matrix semantics, the result contract, tool input/output, or
model-visible error kinds requires a new phase and a new acceptance round.
