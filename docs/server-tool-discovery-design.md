# 服务端工具可靠性与按需发现方案

状态：三家源码调研后的收敛方案，2026-11-05。P0 首批修复和 P1 编码工具集试验配置已实现，默认仍使用完整工具集；固定模型评测、P2 扩展发现尚未执行。本文取代此前以动态加载为主的候选稿。

## 1. 决策

采用「明确的工具契约 + 稳定的编码核心集 + 按协议适配的扩展发现」。模型决定下一步，运行时提供定义、事实和执行边界。

实施分三阶段，每阶段独立验证：

| 阶段 | 交付 | 启用条件 |
| --- | --- | --- |
| P0 契约与观测 | 缺参保护、结果一致、说明一致、编辑失败反馈 | 本地回归通过；保留原暴露方式以单独归因 |
| P1 编码核心集 | 显式 coding profile、模型兼容配置、工具体积记录 | 核心任务覆盖、控制工具可达、执行边界回归通过 |
| P2 扩展发现 | 本地目录检索、普通函数调用的定义加载；原生搜索按需另适配 | 确有扩展需求，且固定模型评测证明收益 |

P1 先在普通交互编码场景受控启用。它是明确限定范围的工具集，不承诺所有已注册扩展都能立即使用；需要其他能力时使用现有显式配置选择集合。P2 才补上按需发现，不能把尚未实现的扩展入口写进 P1 提示词。

第一版暂不建设：额外分类模型、按任务阶段自动切工具、完整 Code Mode／任意代码代理执行器、tool_release、TTL／LRU、通用参数猜测修复、自动业务重试、新数据库。

## 2. 已有故障证据与调研边界

历史 iOSMDM 会话共 681 次工具调用，62 次标记失败，加上 1 次被标成成功的删除拒绝，共 63 次失败或拒绝，约 9.25%。所选问题 Turn 为 90 次调用、23 次失败或拒绝，约 25.56%。这是历史混合口径，不能与其他 Agent 未知任务分布的成功率直接比较。

该 Turn 每次请求带 116 个工具，ToolsPromptChars=72283。这个指标实际是描述与 schema 的 UTF-8 字节长度之和，不是 token 数或完整请求大小。全量定义可能增加负担，但不是全部失败的已证实原因。

历史调用存在编辑字段错名、缺字段、精确匹配失败、猜路径、命令与环境限制、任务记录失效等不同问题。当前编辑实现已有删除保护，仍需区分字段缺失与明确空字符串。随机 free 路由还会切换实际模型，不适合用于单模型因果判断。

三家本地源码提供的是工程参考，未提供同任务、同模型的效果对照：

| 项目 | 已核实机制 | 对本方案的影响 |
| --- | --- | --- |
| DeepSeek Harness | preset／scope／条件解析；步骤定义与执行共用集合；供应商适配 | 显式工具范围与请求快照，兼顾稳定性 |
| OpenCode | 核心原生工具；扩展 Code Mode 搜索签名；模型选择编辑契约 | 常见操作无需先搜索；有限修复与诊断有价值 |
| Codex | 能力控制；本地 BM25；专用 tool_search_output 携带定义 | 原生发现依赖协议，不能普遍套用 |

没有证据支持必须先用额外 LLM 分类步骤，也没有证据支持一套加载生命周期适配所有模型。截图里的操作汇总不能证明后台采用哪种机制。

## 3. P0：先修工具契约和结果反馈

### 3.1 输入与编辑

- edit_file 的 path、old、new 都必须提供；明确的 new="" 与省略 new 是两种输入。缺字段不得转成删除，删除继续受现有 allow_delete 与审批规则限制。
- 对纳入首版的内置工具，schema 与运行时共同拒绝未知字段，错误指出字段名和允许字段；不静默删除 new_string，不猜测它应映射成 new。第三方原始 schema 不统一强行闭合，避免破坏其契约。
- 缺参、空值、类型错误、无匹配、多处匹配和无变化给出明确错误；参数合法不代表操作已完成。
- read_file 的展示行号与原文有清晰边界。成功搜索和失败定位保留源代码缩进，提供可直接用于编辑的原文，避免模型复制展示前缀。
- 编辑失败可返回有限原文、匹配数量或“新文本已存在”的诊断；仅在当前读取权限允许时返回，长度有界。诊断相似度不直接决定修改位置。
- 首版保持现有精确匹配原则，不引入忽略行首缩进的通用 fallback。CRLF／LF 的读写一致性单独验证，未修改内容尽量保留。

通用 JSON／字符串类型修复不是 P0 前提。后续如有高频结构错误证据，仅考虑 schema 无歧义的转换，保留原始与执行参数，并再次校验；绝不补造路径、命令、编辑内容或权限。

### 3.2 说明与命令

统一 run_command 实现、工具主说明、字段说明和相关技能中的 shell 行为。不能一处允许复合命令，另一处笼统禁止；具体执行仍受已有分类、路径与审批控制。

说明必须区分前台等待／命令超时、后台运行、等待中与退出失败。沿用现有 background 与 job_* 能力，并明确 job_wait 的适用场景，避免用长 sleep 轮询。状态仍为 running 不记成命令执行失败。

历史 unknown job 与进程仍在运行的问题另列运行时缺陷：先复现并核对任务所有权、会话重置和存活进程。工具集优化不承诺修复进程跨重启恢复，也不把后台任务持久化系统混入本轮设计。

### 3.3 结果与统计

在现有 ToolResult、Observation、Step 和事件链中统一成功／失败含义，优先复用现有字段；确需新字段时单独验证客户端兼容性。不得仅因 Go error 为 nil 就把业务拒绝记成成功，也不靠匹配自然语言文案推断所有第三方结果。

统计至少区分：参数校验、未知工具／不可用、路径或资源不存在、编辑定位、权限拒绝、等待超时、命令退出失败、执行器／传输故障、取消。分类是诊断信息，不自动触发业务重试。取消和预期权限拒绝单列，不与传输故障合并。

所有计数、持久化与 UI 事件以同一最终结果为依据。保持每次 tool_call 与 tool_result 配对，记录失败前已产生的实际变更，不能把部分修改包装成完全未执行。

## 4. P1：稳定的编码核心集

coding profile 是 runtime 的显式配置，不通过用户消息关键词切换权限，也不在 loop 硬编码业务工具名。完整 Registry 保留；profile 只选择模型可见定义，执行继续经过现有边界。

初始候选按能力配置，最终注册名称和数量在落地时由目录与任务覆盖检查确定：

| 能力 | 首版选择原则 |
| --- | --- |
| 目录、读取、搜索 | list_files、read_file、grep 等满足定位代码的最小组合 |
| 修改已有文件 | 经验证的一种主要编辑契约；普通函数模型优先修复后的 edit_file |
| 新建文件 | 保留确有独立语义的 create_file；不因“单一编辑”丢失新增能力 |
| 命令与任务 | run_command 及其实际依赖的 job_status／job_logs／job_wait／job_cancel |
| 必需控制 | 当前提示词或宿主要求的技能、记忆、提问、计划及进度工具 |

常见读、改、测试不要求先搜索。insert_file、多种补丁入口、Git 包装、LSP、网页、设备、自动化、跨会话及第三方 MCP 不默认全部加入；依据任务范围显式启用或由 P2 提供。工具名不同但行为重复时先选择一种，而非一律合并成复杂 action 枚举。

“单一主要编辑契约”指不同时给模型多种同义替换／补丁格式；并不要求删除有独立用途的新建文件或安全控制能力。某模型确需补丁语法时通过已验证的模型配置选择替代实现，不伪装成另一种工具格式。

profile 必须覆盖提示词中的强制流程，例如 recall_memory、todo、load_skill；不能提示调用未提供的工具。计划模式、只读子代理和 managed 域继续服从原限制，profile 不能扩大其能力。

顺序在同一有效集合内固定，描述避免重复长说明。记录工具数量、定义序列化字节与实际输入／缓存 token（接口提供时），同时计入目录提示、历史定义，不能只看 tools 数组长度。首版不预设 24 个／24 KiB 为硬门槛，也不把中文字符数除以四当精确 token。

## 5. 模型和协议适配

能力由供应商适配器、已验证模型配置及显式覆盖声明；未知模型采用保守路径，不按“名字里含 gpt”推断全部能力，不在失败中途自动切协议。

| 路径 | 定义如何交给模型 | 本方案安排 |
| --- | --- | --- |
| 普通 function calling | 请求 tools 中的完整 JSON schema | P0／P1 默认，P2 通用发现先验证此路径 |
| 原生延迟发现 | 供应商专用搜索调用与结果类型 | 需求明确且能力验证后独立适配 |
| Code Mode／PTC | 程序入口、SDK 或签名与嵌套执行 | 本轮暂缓 |

模型能输出 JSON 并不证明支持工具调用。供应商 schema 投影也必须保留运行时约束，不能因接口不支持某 schema 关键字就取消本地校验。兼容投影只解决表示问题，不保证弱模型能正确选工具和填参数。

Codex 的原生 tool_search_output 是专用协议历史项；普通 function calling 不能用一段工具说明文字替代下一次请求中的定义。服务端配置需明确当前采用的路径，日志可定位实际模型、适配器及定义版本；随机路由不进入固定模型验收。

## 6. P2：最小扩展发现

此阶段独立实现、默认关闭，不阻塞 P0／P1。先支持普通交互编码 Turn 的普通 function calling；原生搜索单独验收。执行始终使用原注册工具，不增加 execute_tool(name,args) 代理。

### 6.1 目录与检索

区分完整 Registered、当前可发现 Eligible 和本次请求 Advertised。普通函数调用路径满足 Advertised ⊆ Eligible ⊆ Registered。禁止能力不进目录；需要执行时审批的能力可被发现，但搜索不授予执行权限。

目录在客户端工具合并后构建，使用受信任名称、分类、标签与描述。本地确定性检索，支持准确名称与有限的中英文标签；不引入另一个模型或向量库。纯中文、英文、准确名称和未知查询必须有离线召回用例，不能因 BM25 存在就声称跨语言效果可靠。

入口暂名 tool_search，query 必填且非空，limit 可选。首个试验配置默认 3、最大 5，只是待验证参数。返回数量同时受定义体积预算约束；命令与任务控制等静态依赖一起计入。首版不做 cursor／分页状态，目录摘要只展示有限类别，不列出全部工具名称和 schema。

找不到匹配返回 no_match；预算不足或单项过大返回明确原因，不裁剪 schema，不自动卸载常驻工具，不靠切回全量绕过限制。预算在测量核心集与扩展分布后配置，配置必须容纳核心集及必要依赖。

### 6.2 普通函数调用中的加载

一次搜索完成选择，成功结果返回准确名称、短说明和 available_from=next_model_request；下一请求 tools 携带完整定义。重复选择幂等，不重复排序；无关扩展不发送。不将选中工具的完整 schema 同时重复放进文本结果。

本次 assistant 响应只能调用其请求快照中的工具。同批搜索再猜测调用尚未展示的工具，后者仍不可执行。选择变更在批次结果提交后生效，由通用受信任控制结果表达，loop 不按业务工具名分支；外部 MCP 文本不能伪造选择变更。

同一 Turn 中追加选择并保持稳定，不做自动卸载。新 Turn 回到核心集；已有后台任务所需控制工具属于核心集，不依赖上轮加载字样。选择状态限当前 workspace／session／turn，不跨会话、fork 或子代理继承客户端资格。

仅保留实现上述语义所需的最少选择状态。同 Turn 压缩不清空状态；暂停／恢复若受支持，必须与现有 checkpoint 一致保存并重验当前目录。保存失败不能先报告 loaded；如暂不能满足该约束，就不对该恢复路径开放 P2，不能静默以空集合继续。进程重启恢复与 schema 变化必须有明确行为，再扩大启用范围。

### 6.3 原生延迟发现

如后续接入供应商原生搜索，可共用 Eligible 目录和检索，结果编码及调用资格由独立协议适配处理。不强迫其维护普通 tools 数组的加载集合，也不因此放宽现有执行资格；必须定义并验证等价的本步资格来源、历史配对、压缩与恢复行为。

## 7. 当前代码落点与兼容范围

下表是职责划分，不预先要求引入新的框架或每项单建 package：

| 位置 | 预期修改责任 |
| --- | --- |
| internal/tools/filesystem、shell | 输入契约、原文反馈、命令说明；保留保护与审批 |
| internal/tools/schema.go 及实际校验入口 | 对首版内置契约表达并执行未知字段规则 |
| internal/agent/tool_batch.go、observation 链 | 统一最终结果与统计；保持调用配对 |
| runtime 的工具组装 | 显式 profile；客户端合并后生成可用集合 |
| internal/agent/tool_defs.go、loop.go | 供应商中立定义与本次请求快照；保持工具无关 |
| model adapters | 验证 schema／协议表示，记录实际模型与请求体积 |
| P2 的小型目录／选择组件 | 检索、选择和预算；需要时接入既有 checkpoint |

当前 toolDefinitions 使用 Registry.Visible()；tool_batch 依 advertised 与已注册条件判定调用。P1／P2 都必须保持请求定义与执行资格一致，不把 RegisterInternal 当成“尚未加载”状态。

旧客户端继续按 register_tools、executor=client、ClientWaiter 注册和执行。核心集选取不改变真实调用名和 call_id；strict_client 断线不得回退服务端执行。诊断优先复用事件，新增字段或事件先验证旧客户端行为。

组合工具与嵌套执行必须同步核对：不能让 Flux 或 ExecuteNestedTool 通过完整 Registry 绕过 profile／域限制。若首批无法完成覆盖，该执行域显式保持原模式。请求期间目录更新不能静默替换当前快照的同名契约。

## 8. 验收

### 8.1 本地确定性检查

| 范围 | 必须通过的用例 |
| --- | --- |
| 编辑保护 | 缺 new、错用 new_string、明确空 new、未授权删除；前三类不误写，允许的明确删除按原规则执行 |
| 编辑行为 | 无／多处匹配、no-op、带展示行号、CRLF、重复代码、中文文本；失败不意外修改 |
| 反馈与观测 | 业务拒绝、命令退出失败、running、取消、超时、客户端错误的结果与计数一致 |
| 核心集 | 读／搜／改／新建／测试闭环，强制控制工具可达，注册大量扩展不扩大初始定义 |
| 边界 | 审批、路径、计划模式、子代理、客户端路由、嵌套执行不被 profile 绕过 |
| P2 独立门槛 | 中英文检索、无结果、重复选择、依赖、超预算、同批越界、并发隔离、目录变化与已开放恢复路径 |

原始历史请求可用于参数重放和归类，修改操作只在临时仓库／文件副本执行，外部副作用使用假执行器。历史参数不能代替固定模型端到端实验，也不能证明改变工具集后模型会生成相同调用。

按变更运行相关 Go package 测试，必要时 go build／go vet；不为文档修改运行完整测试。上线前检查客户端协议和有效工具视图，查看 git diff。真实模型实验需要明确任务与费用范围，本设计不启动付费调用。

### 8.2 固定模型对照

固定具体模型、仓库副本、上下文、权限和采样参数，记录多次独立运行，分阶段比较：

| 组别 | 契约 | 暴露方式 | 回答的问题 |
| --- | --- | --- | --- |
| A | 原有 | 全量 | 基线是什么 |
| B | P0 修复 | 全量 | 契约修复是否有效 |
| C | P0 修复 | P1 核心集 | 常规编码任务是否受益 |
| D | P0 修复 | 核心集 + P2 发现 | 扩展任务能否低成本完成 |

C 与 B 比较核心集可完成的同一任务；扩展任务主要比较 D 与 B，避免把 C 故意未提供的能力当模型失败。稳定基线模型与较弱但支持工具调用的模型分别统计；free 路由另作兼容性观察。

主指标：任务完成率、预期修改正确率、静默错误修改。辅助指标：各类失败次数及调用分母、首次合法调用率、同因重复、失败后恢复、工具定义字节、实际 token／缓存、发现轮数、耗时和费用。权限拒绝独立报告，不能靠减少拒绝来改善表面成功率。

验收硬门槛为契约回归与执行边界通过、已覆盖误写用例为零。模型实验报告样本量与波动；默认推广要求任务完成率和正确性没有明显退步，同时体积、无效重试或总成本有可重复收益。初始 70% 定义缩减只作观察目标，不作为绕过功能覆盖的理由；不能在实验前承诺失败率低于某个百分比。

## 9. 交付顺序与回退

1. P0 分项交付输入保护、结果一致、说明／反馈修复，每项附复现与相关测试。
