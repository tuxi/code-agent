# CodeAgent 会话标题规范

用户发送首条消息后，客户端立即显示消息预览。后端在接收并持久化用户输入后独立生成正式标题，保存成功后主动通知客户端。主回复和标题可以按任意顺序到达。

## 显示与更新

- 标题区域依次选用正式名称 `name`、首条消息预览 `preview`、「新对话」。会话 ID 用于定位会话。
- 发送首条消息时，客户端用本地输入立即展示预览。会话列表和详情接口分别提供 `name` 与 `preview`，刷新和重连后采用相同的显示顺序。
- 后端保存正式标题后推送包含会话 ID 和新名称的更新事件。客户端按 ID 更新对应会话的列表项和当前标题，无需等待主回复结束。
- 一旦有正式标题，后续消息继续沿用该标题。用户可以手动改名。

## 手动改名

- 客户端和 TUI 在用户确认改名时提交。远程客户端复用 `PATCH /v1/conversations/{id}`，提交 `name`。进程内 TUI 从命令面板或通过 `/rename` 打开编辑框，按 Enter 保存。
- 保存成功后，发起改名的一端立即用返回的正式名称更新当前标题和列表项。后端通过同一名称更新事件通知其他已连接的界面，TUI 通过消息循环重绘。列表刷新和重连以已保存的名称为准。
- 保存失败时保留当前显示名称，提示错误并保留用户输入，方便重试。取消编辑时结束当前编辑。
- 手动改名可以发生在自动生成之前、期间或之后。手动名称保存成功后即成为正式名称。自动任务写入时必须确认名称仍为空。名称更新按保存顺序应用，避免延迟到达的自动命名事件把界面改回旧名称。
- 自动标题的 36 字符上限用于模型生成。手动改名沿用现有接口的非空、最多 200 字节校验，由界面按可用宽度显示。

## 客户端接入

- `GET /v1/conversations` 和 `GET /v1/conversations/{id}` 返回可选字段 `name`、`preview`、`name_seq`。名称尚未生成时，`name` 可省略。手动改名成功响应同样返回名称及其 `name_seq`。
- 已订阅会话的客户端收到 `conversation_name_updated` 事件，字段包括 `session_id`、`name`、`seq`。事件独立于回合，客户端可通过会话事件接口按游标重放。
- 客户端为每个会话记录已应用的名称序号。读取 HTTP 响应时使用 `name_seq`，处理名称更新事件时使用 `seq`。乱序到达时保留较大的序号对应的名称。重连时也可重新读取会话详情以同步当前名称。

## 后端命名流程

1. 用户输入持久化后，如果会话没有正式标题，且已有足够的文字信息，启动后台命名。使用最早一条可用于命名的用户消息。首条输入缺少可用信息时，可以等后续消息补足。
2. 每个会话同时最多运行一个命名任务。标题任务使用用户输入生成标题，主回复、工具执行和首轮结果均可独立推进。
3. 校验标题后，仅在存储中的 `name` 仍为空时原子写入。用户在生成期间手动改名时，保留手动名称。已保存的历史名称继续按正式名称展示。
4. 主回复失败时，已启动的命名任务可以继续。命名超时、生成失败或写入失败时，客户端继续显示预览。后端在下一条可用消息持久化后可以再尝试。刷新会话只读取已保存的名称和预览。

服务端命名使用接收回合时选定的 wire model、provider 和凭据解析链。联调时可在 daemon stderr 中按 `[conversation-title]` 和 `session_id` 查找命名记录。生成开始时会记录模型，保存成功时会记录名称事件的 `seq`，失败时会记录阶段和原因。日志只记录诊断字段。

## 长文本与附件

预览和命名输入分别限长。先提取用户意图，再按 Unicode 字符边界裁剪。预览保持单行，客户端按侧栏宽度显示。命名输入保留少量与诉求直接相关的上下文。

| 首条消息 | 预览 | 命名输入 |
| --- | --- | --- |
| 普通短文本 | 显示首条消息 | 使用用户文本 |
| 大段日志附带问题 | 优先显示用户说明，包括日志之后的问题 | 提取日志块前后的说明，补充少量关键报错 |
| 只有日志 | 显示一条可读报错，缺少可读报错时显示「日志排查」 | 有明确线索时使用报错摘要，否则等待后续说明 |
| 图片附带文字 | 显示用户说明 | 使用文字和已有的附件类型 |
| 只有图片 | 单张显示「图片附件」，多张可显示「3 张图片」等数量提示 | 等待用户提供可用于命名的文字 |

## 自动标题格式

- 使用用户的语言，概括主要意图。中文优先 6–12 个字，英文优先 3–6 个词。
- 标题必须非空、单行，最多 36 个 Unicode 字符。保留有助于识别任务的标识，例如 `HTTP 503` 或 `CODE-142`。
- 后端负责落库前校验。标题超长时可请求模型缩写，仍不合格时继续显示预览。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 发送「你好啊，你会做什么」，让主回复继续等待 | 立即显示原文预览。标题任务可以先完成并显示「助手能力咨询」一类短标题 |
| 首轮主回复失败 | 已启动的标题任务仍能完成。生成成功后刷新列表仍显示正式标题 |
| 首次标题生成失败，再发送一条消息 | 期间保留预览，下一条可用消息触发新的尝试。成功后继续发送消息，标题保持稳定 |
| 首条消息夹带大量日志，问题在末尾 | 预览和正式标题体现末尾的实际诉求，中文显示完整 |
| 首条消息只有图片，下一条补充文字 | 先显示附件预览，收到说明后可以生成正式标题 |
| 标题生成期间手动改名 | 保存确认后立即显示手动名称。后台任务返回、旧事件迟到或其他客户端刷新时，仍显示手动名称 |
| 手动改名保存失败 | 保留当前显示名称，提示错误，编辑框保留本次输入 |
| 模型返回多行或超长标题 | 正式名称只接受符合格式的结果，在此期间保留预览 |
